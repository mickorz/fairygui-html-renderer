# 渲染器能力补齐需求文档

> 日期：2026-11-04
> 来源：基于 dev-docs/research/ 下 8 篇三方对比调研（2026-11-04 系列）整理
> 范围：`src/renderer/` 静态 HTML 渲染器的功能补齐需求，按实现优先级排序

## 一、背景与目标

当前渲染器已实现 6 种节点类型（image / text / graph / component / list / loader），全部处于 [部分] 实现状态（loader 仅占位）。与 FairyGUI 原版语义、OpenFairy UGUI 烘焙结果对比后，差距集中在三类：

1. 静默错形：部分属性被忽略后渲染成错误形态而非显式降级（graph 最为严重）。
2. 低成本高收益缺口：overflow 裁剪、valign 等一行到一个文件级的改动，直接提升视觉还原度。
3. 定位边界外：运行时交互类能力（滚动、选中、虚拟化、Transition），明确不做。

目标：在不破坏"静态渲染、未支持如实登记"既有约定的前提下，按优先级补齐前两类。

## 二、范围界定

**做**：构建期可静态计算的视觉与布局能力（几何、样式、裁剪、静态展开、文本排版近似）。

**不做**：运行时交互（滚动拖拽、选中态、虚拟列表、换 url）、动画（Transition、MovieClip 播放）、响应式布局（Relations 同步、容器变尺寸模拟）、骨骼（GLoader3D）、外部资源加载。此类保持 unsupported 占位或明确降级策略。

## 三、需求清单（按优先级排序）

### P0：消除错形 + 一行级高收益（建议立即做）

#### R01 overflow 视口裁剪（component / list）

- 现状：内容超出组件/列表视口不裁剪，overflow=scroll / overflow=hidden 均无效果（parser 未存组件级 overflow 属性）。
- 需求：parser 补存组件级 overflow 属性；component / list 渲染 div 输出 `overflow:hidden`；ScrollPane 场景按首屏观感裁剪（同一实现）。
- 验收：overflow=hidden / scroll 的组件，超出视口的子节点被裁剪；visible 仍全显。
- 涉及：`src/parser/component-parser.ts`、`src/renderer/nodes/component-node.ts`、`list-node.ts`
- 依据：component 篇建议 1、list 篇建议 1
- 成本：小（一处 parser 补属性 + 两个节点各一行）

#### R02 graph 拼写归一与静默错形消除

- 现状：`corner`、`points`、`sides`、`regular_polygon`、旧拼写 `eclipse` 未消费，均静默渲染成矩形。
- 需求：type 判定同时接受 `ellipse` / `eclipse`；未支持的形状属性出现时记入 unsupported 清单，不再静默错形。
- 验收：旧拼写工程（`type="eclipse"`）椭圆正常渲染；带 corner/points 的 graph 出现在未支持清单。
- 涉及：`src/renderer/nodes/graph-node.ts`
- 依据：graph 篇建议 1
- 成本：极小

#### R03 text 垂直对齐 valign + 行距 leading

- 现状：valign 仅上报 unsupported；leading/letterSpacing 未消费，多行文本行高偏小。
- 需求：text 节点改 flex 容器实现 valign（top/middle/bottom -> flex-start/center/flex-end）；行高按 `round(fontSize*1.25)+leading-1` 像素计算（缺省 leading=3）；`letter-spacing` 直出（注意末字符间距口径偏差，可接受或负 text-indent 补偿）。
- 验收：vAlign="middle" 的按钮标题垂直居中；带 leading 的多行文本行距与编辑器一致。
- 涉及：`src/renderer/nodes/text-node.ts`
- 依据：text 篇建议 1-2
- 成本：小（单文件）

#### R04 loader 包内 url（image 分支）+ fill/align 样式

- 现状：有 url 一律进 unsupported；fill/align/vAlign 无样式。基础设施（`parseUiUrl`、image 渲染路径）现成。
- 需求：分两步——(a) fill/align/vAlign 样式计算（空 loader 占位也受益）；(b) url 为 `ui://<pkgId><resId>` 且指向包内 image 时，经 `parseUiUrl` 解析后复用 image-node 渲染路径（注意不可直接 `pkg.byId(url)` 裸 id 查询）。
- 验收：demo 工程中带包内图片 url 的 loader 渲染出图片且填充策略正确；跨包 url 可解析。
- 涉及：`src/renderer/nodes/loader-node.ts`、`src/scene/global-index.ts`
- 依据：loader 篇建议 1-2、注意点
- 成本：小-中（几十行）

### P1：常见视觉特性补齐（第二个迭代）

#### R10 graph rect 圆角与描边

- 需求：`corner`（1 值扩展 4 角，对齐 OpenFairy 的 `radii[min(i,len-1)]` 行为）映射 `border-radius`；`lineSize>0` 时输出 `border:${lineSize}px solid ${lineColor}`，ellipse 配合 `border-radius:50%`，同步摘掉 lineSize 的 unsupported 记录（仅限 rect/ellipse）。
- 涉及：`src/renderer/nodes/graph-node.ts`
- 依据：graph 篇建议 2-3
- 成本：小

#### R11 list item 逐项属性下发（title / icon）

- 需求：XML `<item title icon>` 是作者显式预览数据；expandList 已为每项建场景副本，将 title 写入副本内 name="title" 的 text 节点（复用 injectExtensionProps 的 applyTitle 通路）、icon 写入对应 loader/image。
- 验收：带 title 的列表项渲染出标题文本，与 FairyGUI 编辑器预览一致。
- 涉及：`src/scene/scene-builder.ts`
- 依据：list 篇建议 2
- 成本：小（零架构改动）

#### R12 loader 包内 url（component 分支）

- 需求：url 指向包内 component 时走 scene-builder 场景构建，复用 expandList 跨包展开范式（含循环引用防护与 stableKey 续接）。
- 涉及：`src/scene/scene-builder.ts`、`loader-node.ts`
- 依据：loader 篇建议 3
- 成本：中

#### R13 richtext 节点 + UBB 白名单映射 + 模板 default 替换

- 需求：KNOWN_TYPES 增加 "richtext" 复用 text 渲染路径；UBB 白名单标签映射受限 HTML（[b]/[i]/[u]/[strike]/[sup]/[sub]/[color=c]/[size=n]/[align]，先 `esc()` 再解析保证安全，[img] 复用 ui:// 解析，[url] 降级为带 data-href 的 span）；vars="true" 时按 TextTemplateCompiler 同规则做 `{name=default}` 静态替换。
- 验收：含 UBB 的文本渲染出加粗/颜色等样式；未知标签按原文输出安全降级。
- 涉及：`src/parser/component-parser.ts`、`src/renderer/nodes/text-node.ts`
- 依据：text 篇建议 3-5
- 成本：中

#### R14 image fillMethod 填充

- 需求：进度条、技能冷却高频能力；hz/vt 用 CSS clip-path / linear-gradient 遮罩，radial 系列用 conic-gradient mask 近似，origin/clockwise 按 uGUI 枚举语义映射。
- 验收：fillMethod+fillAmount 的图片呈现部分填充形态。
- 涉及：`src/renderer/nodes/image-node.ts`、`utils.ts`
- 依据：image 篇建议 1
- 成本：中

#### R15 控制器初始页规则对齐

- 需求：parser 的 controller.selected 改为 homePage 规则（缺省第一页），避免编辑器残留选中页导致渲染形态偏移。
- 涉及：`src/parser/component-parser.ts`
- 依据：component 篇建议 4
- 成本：极小

### P2：精度与完整度提升（按需排期）

#### R20 实例级 controller 页覆盖

- 需求：解析 component 子项的 `controller` / `page` 属性，buildScene 展开子场景时覆写对应 controller 的 selected，gear 求值链路自动生效。
- 涉及：`src/parser/component-parser.ts`、`src/scene/scene-builder.ts`
- 依据：component 篇建议 3

#### R21 group 展开渲染

- 需求：`<group>` 节点视为透明容器跳过占位，成员正常显示；进一步做 Horizontal/Vertical 静态排列（改写成员 xy）与 excludeInvisibles。
- 涉及：`src/scene/scene-builder.ts`、渲染层
- 依据：component 篇建议 2

#### R22 image 精度三件套

- 需求：染色 8 位色的 alpha 换算为 opacity（注意与节点 alpha 复合）；nineSliceStyle 增加 `scale === "9grid"` 启用判定；`aspect-ratio` 纵横比。
- 涉及：`src/renderer/utils.ts`、`image-node.ts`
- 依据：image 篇建议 2-4

#### R23 text 排版细节包

- 需求：描边 strokeSize 放大 2 倍补偿口径（或 SVG paint-order 精确实现）+ 缺省值对齐到 1；输入框静态呈现（input=true 渲染 text 或 prompt 浅色斜体，输出 data-fgui-input/password/maxLength）；shadowColor -> text-shadow；bold/italic/underline；singleLine -> nowrap；autoSize=both -> width/height auto + nowrap。
- 涉及：`src/renderer/nodes/text-node.ts`、`parser/component-parser.ts`
- 依据：text 篇建议 6-9

#### R24 list 布局补齐

- 需求：flow_vt 用 `grid-auto-flow:column` 近似；flow_hz 无 lineItemCount 时按视口宽与 itemSize 推算每行列数；item 展开上限 200 改为按视口推算"多留一屏"（或至少提为可配置）。
- 涉及：`src/renderer/nodes/list-node.ts`、`src/scene/scene-builder.ts`
- 依据：list 篇建议 3-4

#### R25 pivot 旋转基点（通用几何）

- 需求：baseStyle 增加 transform-origin（按 pivot 换算），属全部节点共享的几何精度项。
- 涉及：`src/renderer/utils.ts`
- 依据：image 篇建议 5

## 四、明确不做清单（维持 unsupported 登记或占位）

- 运行时交互：滚动拖拽/惯性/翻页、选中态、虚拟列表、树形展开、换 url、DragDrop、输入交互。
- 动画：Transition 播放、MovieClip 帧播放（静态只能渲染首帧或占位）。
- 响应式：Relations 运行时同步、容器变尺寸模拟、useResize。
- 外部资源：外部 url 加载（无运行时）、showErrorSign（unsupported 清单已承担同等职责）。
- 骨骼：GLoader3D（Spine/DragonBones，无渲染目标）。
- graph 运行时 API 项：扇形饼图、多边形贴图、径向渐变、顶点色矩形（无 XML 通道）。
