# fairygui-html-renderer 未来需求计划

- 日期：2026-10-28
- 状态：规划（未排期）；POC 三阶段（P0 解析渲染 / P1 嵌套九宫格 / P2 选择定位）已验收通过
- 说明：本文档记录后续可选演进方向。启动任一方向前，先按项目规范将对应阶段拆解为独立执行计划（含任务表与验收标准），再动手实现。

## 方向一：工作区集成

**目标**：把渲染器接进 FairyGUI Web 工作区，网页端直接浏览本地工程，不再手动跑脚本开 HTML。

**主要内容**

- Node 服务读取本地工程目录（枚举包、按包/组件列出可渲染单元）
- 受限文件 API：只允许访问配置的工程根目录（如 CC-Default），拒绝任意路径访问，防止目录穿越
- 前端按需请求：选包 → 选组件 → 服务端解析生成 Scene Tree JSON → 前端渲染
- 修改本地 XML 后刷新即可看到新结果（重新解析，不做常驻监听）

**前置依赖**：无（可基于 POC 代码直接扩展）

**验收要点**

- 浏览器内从工程 → 包 → 组件三级导航可用
- 路径越界请求被拒绝并返回明确错误
- 修改 XML 后刷新显示新结果

## 方向二：MCP 工具化

**目标**：把渲染与定位能力以 MCP 工具形式暴露给 AI，实现「AI 找到组件 → 画布定位展示」闭环。

**主要工具草案**

| 工具 | 输入 | 输出 |
|---|---|---|
| list_components | 工程根 + 包名 | 组件清单（含实例路径、扩展类型） |
| render_component | 组件实例路径 | 产物 HTML URL / 截图文件路径 |
| locate_component | 组件名或 ID 模糊匹配 | 匹配到的实例路径列表（data-fgui-path 全量索引） |
| screenshot_component | 实例路径 + 视口尺寸 | PNG 截图（供 AI 视觉核对） |

**前置依赖**：方向一（服务化后 MCP 才有稳定入口）；截图需要无头浏览器（Playwright/Chrome DevTools Protocol，届时选型）

**验收要点**

- AI 通过 MCP 搜索「背包头像框」返回的路径能在画布中定位并高亮
- 截图与浏览器实际渲染一致

## 方向三：搜索高亮

**目标**：产物 HTML / 工作区内输入组件名或 ID → 画布定位并高亮目标节点。

**主要内容**

- 构建时生成轻量索引（name/id/path → DOM 节点），内联进产物
- 搜索框 + 结果列表；选中后滚动定位（嵌套组件可能超出视口）、外发光高亮、显示路径
- 多结果（同名节点）支持上下切换

**前置依赖**：无（纯前端增强，可先做在产物 HTML，后并入方向一工作区）

**验收要点**

- 搜索 `closeButton` 定位到嵌套三层内的节点
- 多个同名节点可切换高亮

## 方向四：格式补全

**目标**：扩大可渲染组件类型与工程格式覆盖面，减少未支持清单长度。

**优先级从高到低**

1. **跨包引用（`ui://pkgId+resId` URL）**：list 的 defaultItem 等场景；需要工程级资源索引（当前按单包解析）
2. **fork 格式兼容**：OpenFairy fork 格式（组件 XML 带 fileName、package.xml 无尺寸）与原版格式自动识别
3. **更多组件类型**：ComboBox / ProgressBar / ScrollBar 等常见扩展组件的静态视觉映射
4. **graph 高级**：描边（lineSize）、多边形（polygon）、贝塞尔曲线（考虑 SVG 混合渲染）
5. **transitions 时间轴**：仅展示关键帧列表供 AI 参考，不做动画播放（动画播放属目标 B，明确排除）
6. **movieclip 序列帧**：取首帧静态展示

**前置依赖**：跨包引用依赖工程级索引重构（影响 package-parser 接口）；其余可增量进行

**验收要点**：CC-Default 的 Basics 包 Demo 样本逐个渲染，未支持清单持续缩短；所有新增特性在未支持机制下明确标注边界

## 优先级建议

- 短期先做**方向一**（服务化是二、三的宿主）与**方向三**（纯前端增量，见效快）
- **方向二**在方向一完成后启动；**方向四**按渲染过程中的实际缺口穿插进行（遇到哪个补哪个，不批量铺开）
