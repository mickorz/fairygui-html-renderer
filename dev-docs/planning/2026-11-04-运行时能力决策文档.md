## 二、逐项明细

### N1 ScrollPane 滚动（overflow=scroll/visible 区）

- 现状：只按 overflow 裁剪出首屏观感，内容超出部分被裁掉。
- 若做：`overflow:auto`（一行 CSS，滚动条外观与 FairyGUI 不一致）或 viewport/content 双层结构（外层固定视口 + 内层绝对层，约几十行）。
- 依赖：无；与现有 overflow 裁剪同源。
- 参考：research/component-组件三方对比.md ScrollPane 节。

### N2 选中态（list/tree selectionMode）

- 现状：无选中渲染；list 按 item 静态展开。
- 若做：selectedItem/selectionMode 解析 + 选中项高亮样式（复用 .fgui-selected 高亮链路）；真实点击选中需交互层。
- 依赖：若含点击交互，需 N3 同期的交互层。

### N3 Controller 换页交互（点击切页 + gear 重算）

- 现状：只渲染初始页终态；instance 页覆盖（R20）已支持静态定值。
- 若做：渲染期为每个可点击节点输出 data 属性（目标 controller/page），内嵌一段选择器脚本（component-selector.ts 已有点击基础设施）点击时按 gear 重算节点样式。本质是把静态快照升级为"多页快照 + 页切换脚本"。
- 依赖：选择器脚本扩展；gear 全系已登记（阶段 K），重算逻辑现成。
- 说明：这是"交互式预览"的核心项，做了它 N2/N6/N10 大半顺带。

### N4 虚拟列表（itemRenderer 回调模型）

- 现状：静态展开可视窗口×2，长列表视觉正确、体积可控。
- 若做：无意义——回调模型需要数据源与运行时，静态渲染器无宿主。
- 建议：永久不做，除非项目转型为运行时框架。

### N5 树形列表（GTree）

- 现状：GTree XML unsupported 占位。
- 若做：树节点拉平渲染（缩进层级 + 展开箭头图标静态渲染收起态）；展开交互属 N3 交互层。

### N6 loader 换 url

- 现状：内容构建期一次定型。
- 若做：随 N3 交互层（换页触发 gearIcon 重算）；单独做无触发场景。

### N7 输入框真实输入

- 现状：inputtext 静态呈现 text/prompt/password 圆点。
- 若做：`<input>`/`<textarea>` 元素替换 div（小改动）；提交/校验逻辑属宿主应用。

### N8 DragDrop 拖放

- 现状：完全不解析。
- 若做：无场景；做也是 HTML5 DnD 重新实现 FairyGUI DragDropManager，收益低。

### N9 Transition 动画

- 现状：XML `<transition>` 不解析。
- 若做：转译为 CSS animation/transition（tween 曲线映射 cubic-bezier），属性动画（xy/size/alpha/rotation/color）大部分可映射；复杂组合（序列/延迟/震动）成本高。也可只做"首帧到末帧"过渡的简化版。
- 依赖：transition XML 解析层先建（类似 gear 解析）。
- 参考：research/component-组件三方对比.md Transition 节。

### N10 MovieClip/jta 播放

- 现状：静态渲染单帧（jta 解析器已就绪，帧矩形/PNG 内嵌已破解）。
- 若做：全部帧导出 data URL + CSS `@keyframes` steps 播放（interval/addDelay 已在 jta 头解析）；中成本在帧数多时的产物体积。
- 依赖：仅 jta-node 扩展。

### N11 Relations 响应式布局

- 现状：`<relation>` 不解析；容器尺寸固定。
- 若做：要么 CSS 原生方案（百分比/aspect-ratio 只覆盖 percent 类规则），要么脚本方案（RelationMath 逐规则移植，27 种词表，成本最大）。触发条件应是"预览器支持画布拖拽变尺寸"，否则无重算场景。

### N12 外部 url 资源（http/本地路径）

- 现状：上报 unsupported。
- 若做：http(s) 直通 img src（一行）；本地绝对路径经 toAssetUrl 之外的静态资源目录约定。仅当工程 XML 真的引用外部资源时做。

### N13 GLoader3D（Spine/DragonBones）

- 不可行：需要 Web 侧骨骼动画运行时（spine-ts 等）与资源管线，远超静态渲染器边界。建议永久不做。

### N14 graph 运行时 API（扇形/贴图/渐变/顶点色）

- 不可行：发布 XML 无通道，静态渲染器永远没有输入来源。永久不做。

### N15 位图字体（BMFont .fnt）

- 若做：fnt 文本格式解析 + 字形表渲染（Canvas/SVG 逐字摆位），或预转 WebFont。成本大，仅当目标工程大量依赖位图字体时考虑。
- 关联：普通 ttf/otf 字体走遗留文档 L1（触发式，已有方案）。

## 三、决策建议（供参考，非结论）

1. **若未来做"交互式预览"**：按 N3（换页交互）-> N2/N6（顺带）-> N1（滚动）-> N10（动效）-> N7（输入）顺序，一次性把预览器升级为轻交互产物；N9 视动效需求另批。
2. **若维持静态快照定位**：N4/N8/N13/N14 永久不做；其余项保持 unsupported 如实上报即可，无需任何改动。
3. 决策后请更新本文总表勾选与状态，并同步《遗留特性需求文档-未来批次》的"不做清单"引用。
