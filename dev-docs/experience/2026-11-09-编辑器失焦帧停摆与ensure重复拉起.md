# 编辑器失焦帧停摆导致 ensure 重复拉起编辑器实例

## 问题现象

- FairyGUI 编辑器窗口明显开着（用户可见），但桥的 HTTP（localhost:7531）curl 3 秒超时无响应
- 按误判走 `cli/fgui.mjs ensure` 拉起编辑器 -> 第二个编辑器实例被重复拉起，同一工程双开
- 双开后第二实例抢不到 7531 端口（端口被第一实例占用），两边桥都不可用
- 且事后进程查询发现实例又消失了（双开崩溃或用户手动关闭），状态混乱

## 排查过程

1. 上一轮 ensure 成功 + MCP 验证全通过（桥在线、15 包）
2. 隔一段时间后 ping 7531 超时（窗口仍开着）
3. ensure 内部 ping 也超时 -> launched 第二实例 -> 用户看到双开
4. 事后 Get-Process 查不到任何 FairyGUI-Editor 进程

## 根因

- fairygui-agent-bridge 插件是**单线程帧驱动**：HTTP 请求排队等编辑器帧回调处理
- Unity **编辑器**失焦时帧率大幅节流（EditorApplication.update 近乎停摆），帧驱动插件跟着停摆 -> 桥超时但编辑器进程活着
- 插件虽设 `Application.runInBackground=true`，但该设置对编辑器进程失焦节流的抑制不完全
- `ensure` 的判断只有一条：ping 不通 = 没开 -> 直接拉起。没有先查进程存活，把「失焦停摆」误判成「没开」

## 解决方案

ping 失败时先查编辑器进程再决定动作：

1. `powershell Get-Process FairyGUI-Editor` 查进程
2. **进程在 + 桥无响应 = 失焦停摆**：激活编辑器窗口（用户点一下窗口最简单）-> ping 放宽 10 秒重试 2 次 -> 通了继续；**禁止此时 ensure**
3. **进程不在 = 真没开**：才 ensure 拉起

已写进 skill `.agents/skills/fgui-render-diff/references/compare-flow.md` 前置 3。

## 预防/注意事项

- 对 fgui-render-diff 或任何桥前置检查：ping 超时先查进程，ensure 只作为「无进程」时的最后手段
- 长时间交互前提示用户保持编辑器窗口前台/聚焦，或接受停摆时先激活再重试
- 双开发生后：先用 Get-Process 列出实例与启动时间，按 PID 精确关闭多余实例（保留先启动的），不要全杀
