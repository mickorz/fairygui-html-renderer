# 九宫格 border-image 失效：url 双引号截断 style 属性 + 无尺寸兜底缺失

## 问题现象

- Basics/components/Button.xml 的 n1 背景图（九宫格）不显示，按钮只剩文字。
- 该问题在 workspace（http server）路径下**从九宫格功能上线起一直存在**，此前未被发现。

## 排查过程

1. curl `/view?component=Basics/components/Button.xml` 查渲染产物，n1 的 style 属性：
   `style="left:0px;top:0px;border-image-source:url("/api/assets/.../b7_png.png");border-image-slice:..."`
2. 直接可见根因：style 属性被双引号包裹，内部 `url("...")` 的双引号在 `url(` 处就把属性截断了，HTML 解析器得到的 style 只有半截，九宫格样式全部作废。
3. 修掉引号后浏览器再验：borderImageSource 计算样式正确、图片 200，但节点 **0×0** 仍不可见——第二层问题浮出。
4. 对比 image-node 两个分支：普通分支有 `if (!geo.size && res.width)` 用图原生尺寸的兜底；九宫格分支没有。n1 无 size 属性（FairyGUI 里靠 relation width-width/height-height 拉伸到组件尺寸，relations 属 N11 不做），于是 0×0。

## 根因

1. **CSS url 引号与 HTML 属性引号冲突**：`nineSliceStyle` 输出 `url("...")`，拼进 `style="..."` 时未意识到双引号会截断属性。测试断言只检查子串存在（`border-image-slice:78 86 66 88`），字符串匹配通过但浏览器实际解析失败——**字符串断言不能证明 HTML 合法**。
2. **分支不对称**：同文件内普通图分支有原生尺寸兜底，九宫格分支（div + border-image 是另一条渲染路径）漏了同样处理。

## 解决方案

1. `url("...")` 改 `url('...')`（单引号，CSS 合法且不截断双引号属性）；全仓库 grep 确认仅此一处双引号 url。
2. 九宫格分支补 `if (!geo.size && res.width)` 原生尺寸兜底（与普通分支同款）。
3. 回归断言：`border-image-source:url('...')` 存在且 `url("` 不存在（render 80 -> 81 项）。
4. 浏览器实测收尾：computed borderImageSource 加载、box 85×25、slice 7 11 4 8。

## 预防/注意事项

- **拼进双引号 HTML 属性的任何值，内嵌引号必须换形**：CSS url 用单引号、SVG data URI 用 `%22` 或单引号、文本走 esc()。新写 `style="${...}"` 时先审一遍内容里有没有 `"`。
- 字符串断言（includes/regex）只能证明"内容生成过"，不能证明"浏览器解析得了"；关键视觉链路（border-image/clip-path/filter/mask 这类复杂值）要配浏览器 computed style 或至少 HTML 结构合法性验证。
- 同一节点类型的多个渲染分支（img 路径 vs div+border-image 路径）新增分支时，对照旧分支核对公共兜底逻辑（尺寸兜底、对齐、染色）是否要复制。
