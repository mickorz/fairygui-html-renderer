# server 旧进程跑旧代码：页面刷新不生效

## 问题现象

- 修复按钮 icon 注入 bug 并提交代码后，用户刷新 http://localhost:7788/ 页面，按钮图标仍然不显示。
- 我用本地文件（file:// 直渲染）验证一切正常，但 workspace 页面始终是旧行为。

## 排查过程

1. 对比两条渲染路径：本地 debug 脚本（`tsx dev-examples/.../dbg-icon.ts` 直调 renderHtml）图标正常；HTTP `/view` 路由不正常。
2. 渲染管线相同（同一份 scene-builder/renderer），差异只能在**进程**：`npm run serve`（`tsx src/server/main.ts`）是上一会话启动的常驻进程，早于补丁提交。
3. `netstat -ano | grep :7788` 找到 PID，确认是旧进程占着端口。

## 根因

**代码进程层不热更新**。两层缓存要分开看：

- XML 数据层：server 每请求 `fresh: true` 重解析 XML，改 XML 刷新即生效——这层没有缓存问题。
- JS 代码层：tsx 常驻进程把代码加载进内存后永不更新；代码变更后旧进程继续用旧版函数渲染，页面刷新只是重跑了旧代码。

误判来源：以为"刷新页面 = 拿到最新行为"，忽略了渲染发生在 server 进程内。

## 解决方案

1. 立即解决：`taskkill //PID <pid> //F` 后重启 `npm run serve`。
2. 根治：`package.json` 的 `serve` 脚本改为 `tsx watch src/server/main.ts`——任意源码文件变更自动重启进程。已实测：`touch src/server/server.ts` 后监听端口 PID 自动更换。

## 预防/注意事项

- 排查"改了代码页面没变化"类问题，第一步先确认 server 进程启动时间是否早于代码提交时间（`netstat -ano` 查端口 PID）。
- 长驻开发服务一律用 watch 模式启动（tsx watch / nodemon 等），不要裸 tsx/node。
- 注意区分"数据不生效"（改 XML，fresh 重解析覆盖）与"代码不生效"（必须重启进程）两类症状。
