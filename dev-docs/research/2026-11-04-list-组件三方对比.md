## 1. 组件定位

GList 是 FairyGUI 中功能最强的容器组件，在 GComponent（绝对定位 + 关联系统 + 滚动）之上叠加了四层能力：

1. **自动布局**：五种布局词表（单列/单行/流式横排/流式竖排/分页），自动排列子项、自动计算内容尺寸。
2. **虚拟列表**：数据条数与显示对象数量解耦，只为视口内的条目创建 GameObject，配合 itemRenderer 回调刷新，支撑上千条数据。
3. **交互态**：选中模式（单选/多选/点击切换/无）、selectionController 控制器联动、方向键导航、onClickItem 事件。
4. **树形扩展**：GTree 直接继承 GList，把树节点拉平成列表项管理，支持折叠/展开/缩进/懒加载。

它也是 ComboBox 下拉框、PopupMenu 的底层实现。三套实现 对 List 的投入程度差异极大：原版是运行时全功能引擎；OpenFairy 是"烘焙优先 + 数据源模式"的静态还原；HTML 渲染器是纯静态的一次性展开。

## 2. FairyGUI 原版实现要点（GList.cs 等）

### 2.1 布局词表与 XML 属性

运行时枚举 `ListLayoutType`：SingleColumn / SingleRow / FlowHorizontal / FlowVertical / Pagination，对应 XML 属性 `layout="column|row|flow_hz|flow_vt|pagination"`（缺省 column）。

XML list 节点关键属性（从 UIProject 各包 XML 核实）：

| XML 属性 | 语义 | 二进制对应字段 |
|---|---|---|
| layout | 布局词表 | _layout |
| selectionMode | 选中模式（缺省 single） | selectionMode |
| lineItemCount | 每行/列条数（flow/分页用） | 二进制拆为 columnCount/lineCount 两个字段，按布局取用 |
| colGap / lineGap | 列距 / 行距 | _columnGap / _lineGap |
| defaultItem | 缺省项资源 URL | _defaultItem |
| autoItemSize | 项自动拉伸填满（缺省 true） | _autoResizeItem |
| align / vAlign | 内容对齐（不足视口时整体偏移） | _align / _verticalAlign |
| overflow="scroll" + scroll | 滚动方向 | 触发 SetupScroll 创建 ScrollPane |
| margin / clipSoftness | 边距 / 软裁边 | _margin / clipSoftness |
| renderOrder / apex | 绘制顺序 ascent/descent/arch + 顶点索引 | _childrenRenderOrder / _apexIndex |
| selectionController | 选中联动控制器名 | _selectionController |
| scrollItemToViewOnClick / foldInvisibleItems | 点击滚至可见 / 隐藏项折叠占位 | 版本 2 起字段 |

XML 子节点 `<item title=".." icon=".." name=".."/>` 是作者预置的静态项（运行时可见 PreviewItem），可带 `url` 覆盖单项资源；对应二进制 ReadItems：读每项的 text/selectedTitle/icon/selectedIcon/name，以及组件实例的控制器页与子属性覆盖。

### 2.2 非虚拟布局引擎（UpdateBounds）

所有布局在 UpdateBounds 中逐 child 累积坐标：column 逐项向下累加高度 + lineGap；row 逐项向右累加宽度 + colGap；flow_hz 按 columnCount（或按视口宽度自动换行）折行，行高取行内最大项高；flow_vt 对称按列折；pagination 在 flow 基础上按行数/列数切页，项 x 坐标加上 `page * viewWidth`，内容宽度 = 页数 * 视口宽（横向翻页）。autoResizeItem 开启时项被拉伸：单列项宽度=视口宽；flow 指定列数时按 sourceWidth 比例均分一行宽度（remainPercent 递减算法）；foldInvisibleItems 开启时不可见项跳过占位。

### 2.3 虚拟列表机制

- 入口：SetVirtual() / SetVirtualAndLoop()。要求列表必须 overflow=scroll；loop 只支持单列/单行。
- 数据模型：`_virtualItems` 只增不减，每项 ItemInfo { size, obj, updateFlag, selected }；`_numItems` 是逻辑条数，loop 模式下 `_realNumItems = _numItems * 6`（复制 6 份物理条目实现循环滚动）。
- 布局参数：_curLineItemCount 每行条数（columnCount 或按视口宽与 defaultItemSize 推算），分页布局另有 _curLineItemCount2 垂直条数；滚动步长 scrollStep 直接设为 defaultItemSize。
- 刷新：SetVirtualListChangedFlag 经 Timers.CallLater 延迟一帧合并刷新；RefreshVirtualList 重算内容尺寸并 scrollPane.SetContentSize。
- 滚动复用（HandleScroll1/2）：从 scrollingPos 找到新 firstIndex；对 [firstIndex, 视口末尾] 逐槽位处理——优先在旧条目中按 resourceURL 匹配回收（updateFlag 版本号防止一帧内重复复用），URL 不同则回池换资源；每项回调 `itemRenderer(curIndex % _numItems, obj)` 重绑数据；variable 尺寸变化时 deltaSize/firstItemDeltaSize 补偿滚动位置防跳动；最后一页填不满时循环重试（上限 20 次防死循环）。
- itemProvider(index) 返回项资源 URL，实现异构项（不同 cell 模板混排）。
- 选中态在虚拟模式不依赖 GameObject 存活：ItemInfo.selected 持久化，回收/重建时还原。
- 其他：ScrollToView 按布局推算目标 rect 交给 ScrollPane；GetSnappingPositionWithDir 按条目尺寸+gap 吸附；ResizeToFit 按条数反推列表尺寸。

### 2.4 itemRenderer 回调模型

这是原版的核心编程模型：业务代码设置 `list.numItems = N` 与 `list.itemRenderer = (index, item) => {...}`，列表在虚拟滚动/刷新时回调业务函数把数据写到回收来的 item 上。item 对象由 GObjectPool 管理（GetFromPool/ReturnToPool），同一时刻只有视口附近的项存在。回调同步执行，没有数据绑定，刷新靠重设 numItems 或 RefreshVirtualList 触发。

### 2.5 选中态与事件

- 选中载体是项上的 GButton.selected（项模板用单选按钮模式）；selectionMode = Single / Multiple / Multiple_SingleClick / None。
- SetSelectionOnEvent 复刻修饰键行为：Single 排他；Multiple 无修饰键点击也是排他、shift 范围选、ctrl/cmd 切换；Multiple_SingleClick 每次点击切换。
- selectedIndex / GetSelection / SelectAll / SelectReverse / ClearSelection 全套 API；AddSelection 可联动滚动到可见。
- selectionController 与控制器页数双向同步（HandleControllerChanged / UpdateSelectionController）。
- EnableArrowKeyNavigation 按布局词表计算方向键移动目标；onClickItem / onRightClickItem 事件；scrollItemToViewOnClick 点击自动滚到可见。

### 2.6 滚动（ScrollPane.cs 原版）

Setup 解析滚动类型/滚动条显隐/flags：displayOnLeft、snapToItem、displayInDemand、pageMode、touchEffect、bouncebackEffect、inertiaDisabled、maskDisabled、floating、dontClipMargin（位标志）。运行时提供拖拽滚动（带惯性）、边界回弹（PULL_RATIO 超拉）、滚动条、滚轮（步长 scrollStep）、页面模式、条目吸附、header/footer 下拉刷新（pull down/up release 事件）、clipSoftness 软裁边。虚拟列表挂 onScroll 捕获回调驱动重排。

### 2.7 树形列表（GTree.cs / GTreeNode.cs / Tree/）

GTree : GList。数据侧 GTreeNode 是纯数据树（children/expanded/level/data/resURL），rootNode 是不显示的虚拟根。显示侧把展开的节点拉平成 GList 的子项：CreateCell 从 defaultItem（或节点 resURL）取组件，节点 cell 内名为 "indent" 的子对象宽度设为 `(level-1) * indent` 实现层级缩进；cell 上约定两个控制器："expanded"（展开状态页）与 "leaf"（叶子页），点击带子的节点由 __cellTouchBegin 触发展开/折叠（clickToExpand 可配 0/1/2 次）。回调 treeNodeRender(node, cell) 渲染节点内容，treeNodeWillExpand 支持懒加载子节点（展开前动态插入）。旧版 Tree/TreeView.cs + Tree/TreeNode.cs 是标了 Obsolete 的适配层（同样是"树拉平成列表"思路），被 GTree 取代。

## 3. OpenFairy UGUI 版实现要点（烘焙优先 + 数据源模式）

### 3.1 总体思路差异：回调模式 vs 数据源模式

原版的 itemRenderer 回调 + numItems 是"列表驱动数据"；OpenFairy 反转为"业务驱动列表"：`ListSource.Fill(count, setup)` 一次性传入条数与 `Action<GameObject,int>` 绑定回调，列表内部负责建项/回收/定位。状态与烘焙描述（itemPrefab、itemSize、gap、layout 等）全部序列化在 ListSource 组件上，运行时零 XML、零 URL 解析（SDK 发布范围明确：ui:// 概念只存在于转换期）。FairyGUI 式的 AddItemFromPool/RemoveChildToPool/RefreshVirtualList 增删 API 面不复刻。

### 3.2 Editor 侧：从 XML 静态展开什么（Migrate.cs / FairyXml.cs / ListLayoutBuilder.cs）

FairyXml.cs 用 XmlEnum 声明了 XML 词表：layout 的 column/row/flow_hz/flow_vt/pagination（另有 hz→row、vt→column 的旧别名折叠），selectionMode 的 single/multiple/multiple_singleclick/none。Migrate 期对每个 list 节点：

- AddComponent&lt;ListSource&gt;，烘焙 itemPrefab（defaultItem 解析成 prefab 直接引用）、itemSize（取 prefab 设计尺寸）、lineGap/colGap/lineItemCount/alignment/layout/renderOrder/apexIndex/count（XML item 数）。
- 非虚拟静态项逐个 Instantiate 为 prefab 实例：单项可用 `item url` 覆盖资源（存进 variantItems 数组，与 itemPrefab 并列）；ConfigureButton 配置项按钮面（非 button 项跳过）；ConfigureInstanceControllers 应用项的实例控制器页。
- 按 layout 词表在烘焙期算好每个项的绝对坐标（与原版 UpdateBounds 同规则的 x/y 累积、lineItemCount 或按视口宽自动折行）；autoItemSize 单列拉伸宽到视口宽 / 单行拉伸高到视口高；内容尺寸汇总后 SetGrips 配滚动条。
- overflow=scroll 时 BuildScrollView 烘 viewport + content + RectMask2D + ScrollPane + AuthoredScrollbar。
- selectionMode != None 挂 ListSelection；XML selectionController 属性经 BuildSelectionController 烘成 GearListSelection 泛型 gear，实现控制器页与选中索引双向同步。
- SingleRow 非虚拟布局由 ListLayoutBuilder.Configure 烘成原生 HorizontalLayoutGroup + ContentSizeFitter（子项不控制尺寸、spacing=colGap、Descent 用 reverseArrangement；Arch 与虚拟模式放弃原生行布局）。
- 单项不再假定是 button：defaultItem 为普通 component/label 的列表可用。

### 3.3 VirtualListLayout：纯函数虚拟化

VirtualListLayout.cs 是无状态静态类，只做索引/几何计算，不持有滚动、GameObject、选中：FixedRange 按 `(itemCount-1)/lanes+1` 行数、步长 `itemExtent+gap`、overscan 默认 1 行，算出视口内 [First, End) 物理槽位区间；FixedExtent 算内容总长；VariableRange 用前缀和数组 starts + 二分（LowerBound/UpperBound）支持变高行；LoopRebase 把无界物理槽位流按周期回卷（同时平移滚动位置与槽位序号，视口内像素不变）；LogicalIndex 做物理槽位到逻辑索引的取模。变高行只支持虚拟 SingleColumn；loop 只支持 SingleRow；Pagination 无虚拟化分支。

### 3.4 ListSource 运行时

- 对象池：ObjectPool&lt;GameObject&gt;，池根是隐藏节点 `__listPool`；回收项 SetActive(false) 移回池根；作者预置的变体项回收时保留对象不销毁（ReleaseChildren 中 variantItems 直接藏回池根）。
- Fill（非虚拟）：全量建项、绝对定位（或 SingleRow 交给原生 LayoutGroup）、按 alignment 整体偏移（AlignmentOffset，等价原版 HandleAlign）、刷滚动内容、重绑 ListSelection。
- Fill（虚拟）：记录锚点物理槽位与偏移保证续滚不跳；清空可见集后按 FixedRange/VariableRange 补齐缺口，每槽位建项、定位、`setup(item, logicalIndex)` 绑数据；变高行测高后 repeat 循环直到区间稳定（重算 starts/内容尺寸并 Rebase 滚动位置）。
- 滚动驱动：ScrollPane.onScroll（UnityEvent）触发 UpdateVisible；LateUpdate 监视视口尺寸变化自动重 Fill。
- 环保设计：version 计数 + IsBound(item, index, fillVersion) 让异步绑定器识别"回收后的旧绑定"，拒绝过期写入（原版用 updateFlag 版本号解决同类问题）。
- 其他：ScrollToIndex（支持居中/动画）、SnapPosition（条目步长或变高行吸附）、firstVisibleIndex/centeredIndex、renderOrder Descent/Arch 用 SetSiblingIndex 复刻绘制顺序（项索引与位置不变）；ResetButtons 回收时清 selected/grayed/changeStateOnClick。

### 3.5 选中态（ListSelection.cs / ListSelectionItem.cs）

- ListSelection 是 UIBehaviour + IPointerClickHandler，挂 list 根；selectionMode 同原版四值词表。
- 点击路由：按钮项经自身 onClick（ListSelectionItem 中继，Bind 时记版本号，重绑后旧回调作废）；非按钮项点击冒泡到列表根，由 OnPointerClick 反查落点所属项，同样发 onClickItem——复刻原版"对任意类型项派发"。
- Click 语义复刻 SetSelectionOnEvent 的无修饰键路径：Single/Multiple 排他选中，MultipleSingleClick 切换（未实现 shift 范围选与 ctrl 单项切换的修饰键分支）。
- 选中索引集 HashSet&lt;int&gt; 独立于 GameObject 存活（虚拟模式回收不丢选中，等价原版 ItemInfo.selected）；Rebind 时虚拟模式按索引集回填按钮 selected。
- selectedIndex/GetSelection/ClearSelection API；selectionController 双向同步（SelectFromController / UpdateSelectionController + 防环 _updatingController）。
- 点击总是发 `UnityEvent<int> onClickItem`（含非按钮项），ComboBox 下拉自管选择（Build 时禁用列表自带 ListSelection）。

### 3.6 滚动（ScrollPane.cs / AuthoredScrollbar.cs）

OpenFairy ScrollPane 直接继承原生 ScrollRect（"滚动交互由原生 ScrollRect/Scrollbar 承担"）：拖拽（touchEffect）、滚轮、弹性回弹（MovementType.Elastic）、惯性（decelerationRate 烘 0.967^60）、SetPosition/percX/percY/ScrollToView/Step、snapToItem 与 pageMode 的视口取整吸附（LateUpdate 停稳后 Snap）、loopHorizontal（Unrestricted + Rebase）、hover/drag 时 autoHideBars 自动显隐滚动条（CanvasGroup）。位置以左上原点 Vector2 暴露（position = -content.anchoredPosition 修正 y 轴），对齐 FairyGUI 坐标语义。AuthoredScrollbar 继承原生 Scrollbar：grip 拖动、轨道点按跳 4 倍步长、箭头 Step、size 0~1 外自动隐藏 grip。明确不做：下拉刷新、分页吸附外的页惯性细节、惯性/回弹常数逐帧复刻（近似值）。

### 3.7 OpenFairy 边界（未复刻部分）

GTree/GTreeNode 树形无对应实现；折叠不可见项（foldInvisibleItems）、方向键导航、shift/ctrl 修饰键多选、Pagination 布局的翻页吸附（排布按 flow_hz 处理）、虚拟分页、按列折行的 flow_vt 虚拟化（虚拟 lanes 统一按 lineItemCount/视口推算）均未实现或做了简化。

## 4. 当前 HTML 渲染器实现要点

### 4.1 定位与边界

当前实现是**纯静态渲染器**：把 FairyGUI 包 XML 一次性转换为静态 HTML 片段，目标是视觉还原与节点定位（供预览、截图对比、MCP 工具），不是运行时 UI 框架。因此 List 只保留"布局 + 静态包内 item 展开"这一层，其余运行时能力全部如实标记为不支持，无隐藏的近似模拟。

### 4.2 数据流（scene-builder.ts / component-parser.ts）

1. 解析层（component-parser.ts）：list 节点登记 `itemCount` = XML `<item>` 子元素个数（仅计数）。
2. 构建层（scene-builder.ts expandList）：需要 SceneOptions.root 才能解析 `ui://` defaultItem；解析后取 defaultItem 组件的设计尺寸写入 `defaultItemSize`（对应原版 GList item 尺寸语义），然后为每个 item 生成一份 defaultItem 组件的完整场景树副本 `listItems[i] = { index, scene, pkg }`。副本继承主构建流程的 instancePath（`...item{i}`）与 stableKey（`...#i~pkgId.resId`），循环引用防护（stack）与逐节点副本隔离（不污染解析缓存）同样生效。数量上限 `Math.min(itemCount, 200)` 防爆。
3. 渲染层（list-node.ts）：对每个 item 场景递归 renderChildren，包一层显式尺寸的 wrapper（子节点全部 absolute 定位，不贡献尺寸，必须靠 defaultItemSize 撑起）；list 容器按布局词表输出 CSS。item 内容不运行时从 defaultItem 建项——静态展开即等价于 OpenFairy 烘焙期那次展开。

### 4.3 布局映射（list-node.ts）

| SDK 词表 | CSS 实现 | 状态 |
|---|---|---|
| column（缺省） | flex column，gap 行距 | [已实现] |
| row | flex row，gap 列距 | [已实现] |
| flow_hz | lineItemCount > 0 时 grid `repeat(lineItemCount, max-content)`，gap 行距 列距 | [已实现]（依赖 lineItemCount，无自动按视口宽折行） |
| pagination | 同 flow_hz 的 grid 排布 | [部分实现]（仅排布，无翻页语义） |
| flow_vt | 落入缺省分支，按 flex column 渲染 | [部分实现]（多列纵向折列未做，退化为单列） |

overflow 一律输出 `overflow:hidden` 硬裁剪（无视口、无滚动、无软裁边）。gear 系统对 list 容器本身生效（gearXY/gearSize/gearDisplay/gearColor 在分发层 resolveGear 统一处理），item 场景内部的 gear 也随通用节点渲染生效（默认页取值）。节点输出 data-fgui-* 溯源属性（id/name/src/type/instancePath/stableKey），供选中器与 Scene Tree JSON 定位。

### 4.4 已实现清单

- [已实现] defaultItem（ui://）解析与静态展开，item 逐份场景副本，含子组件递归与 gear 默认页。
- [已实现] column/row 布局 + colGap/lineGap；flow_hz/pagination 按 lineItemCount 网格换列。
- [已实现] defaultItemSize 取 defaultItem 组件设计尺寸，item wrapper 显式定宽高。
- [已实现] 展开数量上限 200（防超大静态包）；无 item 且 defaultItem 不可解析时红虚线占位并计入未支持清单。
- [已实现] stableKey/instancePath 全链路（`列表键#索引~包.资源`），渲染 HTML 与 Scene JSON 一致。
- [已实现] list 容器与 item 内节点的 gear 默认页解析。

### 4.5 未实现清单（静态渲染边界，如实声明）

- [未实现] 虚拟列表（numItems/itemRenderer/回收复用）——静态包内有多少 item 就展开多少，上限 200。
- [未实现] 滚动：overflow=scroll 不产生滚动容器/滚动条/惯性/回弹，仅 overflow:hidden 裁剪。
- [未实现] 选中态：selectionMode/selectionController/onClickItem/方向键导航全部不支持，无交互。
- [未实现] 树形列表（GTree/GTreeNode 缩进/折叠/懒加载）。
- [未实现] 运行时增删 item（AddItemFromPool 等 API、Fill 语义）——渲染产物是死 HTML。
- [未实现] 翻页（pagination 页宽堆叠与吸附滚动、pageController 联动）。
- [未实现] `<item>` 逐项属性（title/icon/name/selectedTitle/实例控制器页）——当前只统计个数，所有项都用 defaultItem 模板渲染，逐项数据被丢弃。
- [未实现] 逐项 `url` 资源变体（OpenFairy 的 variantItems 对应能力）。
- [未实现] autoItemSize/autoResizeItem 拉伸、align/vAlign 对齐偏移、margin、clipSoftness、renderOrder/apex、foldInvisibleItems。
- [未实现] flow_vt 的按列折列（多列纵向流）；flow_hz 无 lineItemCount 时按视口宽自动折行。

## 6. 结论与可补齐建议

三方的本质差异是**执行时机**：FairyGUI 在运行时按数据流实时布局/回收；OpenFairy 把"布局解算、项实例化、交互接线"整体前移到 Migrate 烘焙期，运行时只留数据源填充与滚动；HTML 渲染器把一切冻结在构建期一次性输出。HTML 渲染器当前已覆盖"静态包能看"的主路径，短板集中在三处，按性价比排序：

1. **overflow=scroll 的视口裁剪补齐**：目前 list（及 overflow=scroll 容器）只有 overflow:hidden，内容超出视口即被切掉。最低成本补法是给列表容器输出固定宽高 + overflow:hidden 已有，可进一步输出内层可滚动结构（viewport 固定 + content 绝对定位层），或至少在未支持清单中提示"内容超出视口 x/y 像素"。纯静态产物若要可滚动，overflow:auto 是一行 CSS 的近似（ scrollbar 外观与 SDK 不一致，需按产物定位取舍）。
2. **`<item>` 逐项属性下发**：XML 里 `<item title icon>` 是作者显式写的预览数据，丢弃后 HTML 与 FairyGUI 编辑器预览不一致。scene-builder expandList 已经为每项建了场景副本，把 item 的 title 写入副本内 name="title" 的 text 节点（复用 injectExtensionProps 的 applyTitle 通路）、icon 写入对应 loader/image，即可零架构改动对齐预览。
3. **flow_vt 折列与 flow_hz 自动折行**：flow_vt 可按 lineItemCount（或视口高与 defaultItemSize 推算）用 CSS grid `grid-auto-flow: column` 近似；flow_hz 无 lineItemCount 时按视口宽与 itemSize 推算每行列数再走现有 grid 分支。两者都是构建期可算的静态几何，不需要运行时。
4. **item 数量裁剪上限语义化**：200 上限目前是硬编码防爆值；可改为按视口尺寸推算"视口外多留一屏"的可见窗口展开（OpenFairy 的 overscan=1 行思路），既保视觉又控体积；至少把上限提为可配置。
5. **clipSoftness 软裁边**：可用 CSS mask-image 渐变近似，属于视觉细节，优先级低于以上四项。

不建议补齐的：虚拟列表、选中态、滚动交互、树形——这些是运行时能力，与静态渲染器定位冲突；若未来出现"可交互预览"需求，应另起交互层而不是把渲染器改成框架。
