# Loader 组件三方实现对比调研（兼顾 GLoader3D）

日期：2026-11-04
范围：FairyGUI 原版 C#（GLoader / GLoader3D / AsyncCreationHelper）与 OpenFairy UGUI 转换（Loader + Editor/Migrate）与本项目 HTML 渲染器（loader-node）
说明：参考仓库 thirdparties/OpenFairy-SDK-uGUI 无 LICENSE，本文只描述解析行为与格式知识，不复制其源码（引用不超过 3 行）。

## 1. 组件定位

GLoader 是 FairyGUI 的动态加载占位容器：设计期只是一块矩形占位（常作为按钮图标、列表项图标、头像框），运行时通过 `url` 属性按需加载内容并填充显示。与 GImage 的本质区别：GImage 的图片在编辑器发布时就绑定死（`src` 指向包内资源，静态数据），GLoader 的 `url` 是给运行时留的插槽，业务代码随时 `loader.url = "ui://..."` 换内容，也能指向外部纹理。它继承 GObject，实现 IAnimationGear（playing/frame，供序列帧播放）与 IColorGear（染色）。

GLoader3D 是姊妹组件：占位容器不变，内容从 2D 纹理换成 Spine / DragonBones 骨骼动画（经 GoWrapper 包裹 GameObject 呈现），并增加 animationName / skinName / loop 等骨骼属性；填充策略与 GLoader 完全同构。

在编辑器发布的组件 XML 中，loader 是 displayList 的常见子节点，实际工程样例（UIProject/Bag、Basics）形如：

```xml
<loader id="n4" name="icon" xy="6,6" size="88,88" align="center" vAlign="middle" fill="scale"/>
<loader id="n1" name="n1" xy="27,67" size="90,90" url="ui://9leh0eyfwa8u2t"/>
```

可见两类用法：无 url 的纯占位（运行时由业务填充，如 BagGridSub 的 icon 格子）；有 url 的静态引用（编辑器里直接指定了包内资源）。

## 2. FairyGUI 原版实现要点

### 2.1 GLoader（GLoader.cs）

文件：`thirdparties/OpenFairy-SDK-uGUI/Assets/FairyGUI/Scripts/UI/GLoader.cs`

- 内部结构：displayObject 是一个 Container；`_content` 为 MovieClip（可作单帧图片或逐帧序列动画），`_content2` 为加载包内组件时创建的 GComponent；两者互斥。`sourceWidth/sourceHeight` 记录内容原始尺寸，供填充策略计算。
- url 格式与加载入口：`LoadContent()` 先 `ClearContent()`（释放外部纹理、Dispose 旧组件、移除错误占位），然后：
  - url 为 `ui://` 前缀（`UIPackage.URL_PREFIX`）-> `LoadFromPackage`；
  - 其他任意字符串 -> `LoadExternal()`，默认实现是 `Resources.Load(_url, Texture2D)`，虚方法可被子类覆写以接自有加载管线（PuERTS 下可注入 `__loadExternal` 委托）。
  - 注意：运行时只识别 `ui://` 一种前缀；编辑器内置图标（icon:// 等）只在编辑器环境有意义，运行时不存在专有分支。
- LoadFromPackage 按 PackageItem 类型三分支：
  - Image：把纹理、textureScale（分支/高清缩放比）、scale9Grid、scaleByTile、tileGridIndice 设置到 MovieClip,loader 内容同样享受九宫格与平铺。
  - MovieClip：设置 interval / swing / repeatDelay / frames，成为播放中的序列帧。
  - Component：`UIPackage.CreateObjectFromURL(itemURL)` **同步**创建 GComponent；结果非 GComponent 则 SetErrorState。
  - 其他类型（sound/font/swf 等）：autoSize 时先把自己 SetSize 成资源尺寸，然后 SetErrorState 并打警告日志。
  - 找不到 item -> SetErrorState。
- showErrorSign 错误占位：加载失败时，若 `showErrorSign`（XML 可配，默认 true）且 `Application.isPlaying` 且 `UIConfig.loaderErrorSign` 配置了资源 URL，则从包里创建错误占位组件、SetSize 成 loader 尺寸后 AddChild 显示。非播放态（编辑器）不显示。
- 填充策略 UpdateLayout（GLoader 与 GLoader3D 逐行同构的核心逻辑）：
  - 无内容且 autoSize -> SetSize(50, 30)（无内容的默认占位尺寸）。
  - autoSize：按内容原始尺寸调整自身大小（考虑 GX/Y 尺寸限制可能不等，留待后续处理）。
  - fill 五种填充（FieldTypes.FillType：None / Scale / ScaleMatchHeight / ScaleMatchWidth / ScaleFree / ScaleNoBorder）：计算 sx/sy 缩放比，None=原尺寸，Scale=取 min（等比留边），ScaleNoBorder=取 max（等比裁边），MatchHeight/Width=单轴对齐；`shrinkOnly` 只允许缩小不允许放大（sx/sy 超 1 时钳回 1）。
  - useResize（v7+ 新增，仅 GLoader）：组件内容不用缩放而用 `SetSize(w, h, true)` 让子组件真实改变尺寸（配合其内部 relation 自动重排）。
  - align（Left/Center/Right）与 verticalAlign（Top/Middle/Bottom）：内容缩放后在容器内居中/贴边偏移。
- 属性集：url（setter 去重后 ClearContent + LoadContent + UpdateGear(7)，gear 序号 7 即 gearIcon,url 可被控制器驱动切换）、icon（直接映射 url）、align / verticalAlign / fill / shrinkOnly / autoSize / useResize、playing / frame / timeScale / ignoreEngineTimeScale / Advance（动画）、color（染色）、material / shader、fillMethod / fillOrigin / fillClockwise / fillAmount（进度式填充）、texture（外部直接喂纹理，url 置 null）、filter / blendMode。
- 二进制发布数据（Setup_BeforeAdd segment 5）依次读取：url、align、vAlign、fill、shrinkOnly、autoSize、showErrorSign、playing、frame、color（可选）、fillMethod（非 None 再读 origin/clockwise/amount）、useResize（版本 >= 7）；**有 url 时构造即同步 LoadContent**。
- XML 编辑器格式属性（由真实样例归纳）：通用属性 id/name/xy/size/pivot/scale/grayed 等，loader 特有 url / align / vAlign / fill；autoSize / shrinkOnly / errorSign 等低频属性在本仓库全部 30+ demo 包的实际实例中未出现。

### 2.2 GLoader3D（GLoader3D.cs）

- url 同样只认 `ui://` 前缀：LoadContent 里 `UIPackage.GetItemByURL` 找 item（同时把自己注册进 item.skeletonLoaders，便于热更重载），按 PackageItemType 分发 Spine / DragoneBones（各自由宏开关 FAIRYGUI_SPINE / FAIRYGUI_DRAGONBONES 包裹）；**找不到包内 item 时走 LoadExternal 虚方法**（基类空实现，由用户子类接自有骨骼资源管线），没有 showErrorSign 机制。
- 内容载体是 GoWrapper（包裹渲染一个 GameObject），骨骼实例创建后 `SetWrapTarget` 设置并记录 sourceWidth/Height。
- 骨骼属性：animationName / skinName / playing / frame / loop，任一 setter 触发 OnChange 通知当前骨骼实例；timeScale / ignoreEngineTimeScale / Advance 标注 Not implemented（占位 API）。
- UpdateLayout 与 GLoader 相同（fill / shrinkOnly / autoSize / align / vAlign），但没有 useResize、没有错误占位。
- 二进制属性：url / align / vAlign / fill / shrinkOnly / autoSize / animationName / skinName / playing / frame / loop / color。

### 2.3 异步创建（AsyncCreationHelper.cs）

- GLoader 的包内 Component 分支本身是**同步**创建；AsyncCreationHelper 提供通用的按帧分片异步组件创建：`CreateObject(item, callback)` 启动协程，先递归收集目标组件全部子项类型信息（CollectComponentChildren 递归、CollectListChildren 处理 list 的 defaultItem），再逐项 NewObject + ConstructFromResource，每处理 5 项检查一次实际耗时，超过 `UIConfig.frameTimeForAsyncUIConstruction` 就 yield 一帧，避免大组件一次性构造卡帧。
- 细节：全部子项放进对象池再由 GComponent/GList 消费；若整个过程没让出过帧，仍强制 yield 一帧后才回调，避免调用方时序错乱。
- 该机制不是 GLoader 内建调用的，而是供业务代码（或上层封装）对"loader 加载组件"场景自行使用的分帧工具。

## 3. OpenFairy UGUI 版实现要点

### 3.1 设计取舍：烘焙优先，运行时零 URL

AGENTS.md 明确记录：本 SDK "Resource URL 加载、动态/异步资源加载：一律用 Unity 直接引用，Loader/MovieClip 的帧与内容都在 Migrate 期烘成 Sprite/prefab"，且 "不运行时解析 URL"。即 loader 在 OpenFairy 里不是动态加载容器，而是"编辑器里已经决定好的内容"的静态快照。运行时换 url、showErrorSign、shrinkOnly 均无实现（全仓库 grep 无相关代码）。异步也不需要，烘焙期同步完成。

### 3.2 Runtime/Loader.cs

- `OpenFairy.UGUI.Loader` 继承 `MovieClip`（后者继承 uGUI Image、逐帧播放序列帧），因此 loader 天然支持图片与序列帧两种内容，组件内容用互斥状态叠加。
- 字段：fill / align / vAlign 三个枚举（值域与原版 FillType/AlignType/VertAlignType 对齐，含原版的 ScaleFree）、autoSize、`componentContent`（[SerializeField] internal，预烘焙进 prefab 的组件内容实例引用）、`componentSize`（组件内容设计尺寸，autoSize 用）、`_showComponent` 私有互斥标志。
- 内容切换：
  - `sprite` setter（换图）：停止播放、隐藏 componentContent、置 base.sprite。
  - `ShowContent()`（切组件）：清 sprite、激活 componentContent 的 GameObject、autoSize 时 SetNativeSize 后 LayoutContent。
- 填充与对齐：`LayoutContent` 用 `Scale()`（五种 fill 全实现，公式与原版一致：min/max/单轴）算 child.localScale，`Offset()` 按 align/vAlign 算 anchoredPosition 偏移；图片内容则在 `OnPopulateMesh` 中对 Simple 模式自绘 4 顶点（处理 sprite padding / outerUV），保证 fill 缩放后图像正确呈现；Sliced/Tiled/Filled 走 uGUI 基类。
- autoSize：图片走 `SetNativeSize()`；组件用 componentSize；无内容时 `(50, 30)`，与原版无内容默认占位尺寸一致。
- 无内容（url 为空）时 `_showComponent=false` 且 sprite 为 null，OnPopulateMesh 清空网格，loader 就是一块空白矩形，占位视觉交给作者在编辑器摆的其他节点。

### 3.3 Editor 侧（Migrate.cs Loader 分支）

- Schema：FairyXml.cs 的 DisplayKind.Loader 对应 XML `<loader>`；属性映射 fill（LoaderFill 枚举，XML 词表 none/scale/scaleMatchHeight/scaleMatchWidth/scaleFree/scaleNoBorder）、align、vAlign、autoSize（`autoSize="true"` 显式出现才置位，存为 LoaderAutoSize）。
- 转换流程（Migrate.cs 约 1031 行 case DisplayKind.Loader）：
  1. NewChild(typeof(Loader))，烘 fill/align/vAlign/autoSize 四属性。
  2. url 静态解析：`TryResolve(url, owner.PackageId, out content)`,`ui://` 前缀剥掉后在资源字典按 `pkgId+resId` 查（注释明确：编辑器源 XML 里引用一律是 hex id，命名引用 `ui://Pkg/Name` 只出现在运行时代码，这里读不到）；无前缀则默认当前包。解析不到的引用被跳过，不抛异常。
  3. 按资源类型三分支：
     - Image -> `LoadSprite` 取 Sprite + ConfigureImage（九宫格 border、fillMethod 等），loader 当静态图。
     - MovieClip -> ConfigureMovieClip 烘帧序列，loader 当序列帧播放器。
     - Component -> `PrefabUtility.InstantiatePrefab(LoadPrefab(content))` 直接实例化子组件 prefab 为子物体，anchorMin/anchorMax/pivot 统一设 (0,1)（左上角基准），记 componentSize 后 `ShowContent()`，即"预烘焙 Component content"，AGENTS.md 记录其按 native 尺寸整体缩放、GPU 对照通过。
  4. 三分支都不命中（url 解析不到或类型不支持）-> `loader.enabled = false`：组件整个禁用，不占渲染也不报错。
- 实例层级使用：Button/Label 的图标子节点经 `IconLoader()` helper（1481 行附近）向上归一成 Loader 引用，供 selected icon 等预烘多 sprite 绑定（icon 字符串在 Migrate 期解析成 Sprite 直接赋 icon）。
- SetRect 之后对 `autoSize: true` 的 loader 再补一次 SetNativeSize（1114 行），因为 autoSize 结果依赖最终 rect。

## 4. 当前 HTML 渲染器实现要点

### 4.1 现状（loader-node.ts，14 行）

- 无 url：渲染灰底占位 div（`background:rgba(255,255,255,.08); border:1px solid #666` + 居中 "Loader" 小字），**不进 unsupported 清单**，这是有意为之：运行时由业务填充的插槽在静态渲染下本来就没有内容，占位即忠实还原"设计期空 loader"。
- 有 url：仍是同一块灰底占位，同时 `unsupported.push({ reason: "loader url=... 渲染未实现" })`。即 url 内容完全未渲染，只在页面底部未支持清单里登记。
- 已正确复用的公共能力：resolveGear（gearDisplay 隐藏、gearXY/gearSize 页值）、baseStyle（xy/size/rotation/flip/alpha）、dataAttrs 溯源。gearIcon 未在解析范围（GEAR_KINDS 只注册 display/xy/size/color 四种），即控制器切 url 的联动静态渲染下本来也不存在，与"静态单帧"的渲染模型一致，不算 loader 特有缺口。

### 4.2 有 url 时的实际可行性核实（以代码为准）

结论：**url 指向静态包内资源时补齐是实际可行的，且基础设施全部现成，未做属于缺口而非能力边界。**

- URL 解析：`src/scene/global-index.ts` 已实现 `parseUiUrl(url, index)`，识别 `ui://` 前缀、按最长 pkgId 前缀消歧、跨包查资源。list 的 defaultItem（同为 ui:// 引用）已在 scene-builder 的 expandList 里用同一机制成功落地，loader 直接复用即可。
- url 指向包内 image（demo 中最常见，如 `url="ui://9leh0eyfwa8u2t"` 指向图片）：parseUiUrl 命中 kind:"image" 的 ImageResource（含 file/width/height/scale9grid/scale），随后可整段复用 image-node 的渲染路径：`ctx.toAssetUrl(res.file)` 出 `<img>`、nineSliceStyle 出九宫格 border-image、tintStyle 染色。估计改动量：loader-node.ts 内一个 image 分支（约 20-30 行）+ 支持 fill/align/vAlign 的样式计算（fill 五种在 CSS 里用显式 scale/width-height 计算，或 `<img>` 包 div + object-fit 近似；精确对齐原版需手算 sx/sy，约 20 行）。
- url 指向包内 component：scene-builder 的 expandList 已示范完整模式,parseUiUrl 命中 kind:"component" -> loadPackage（跨包）-> getComponent -> buildScene 递归展开（含循环引用防护、stableKey 续接）。loader 需要在 scene-builder 加一个对称分支（loader 有 url 时构建 childComp 副本），渲染复用 component-node 的递归 div。估计改动量：scene-builder 约 30-40 行 + loader-node 渲染 childComp 约 10 行。注意 fill/useResize 语义：原版组件内容默认按 scale 缩放（useResize 才 SetSize），静态渲染照 scale 缩放即可。
- url 指向 movieclip/jta：package-parser 把这类归为 kind:"other"，帧序列数据（interval/frames/图集）完全未解析，需要另做 MovieClip 帧渲染设施（demo 中 loader 引用 movieclip 的实例极少）。建议先维持 unsupported 登记。
- 外部 url（非 ui://）：静态渲染无运行时文件系统语义，无从加载，维持 unsupported（与原版 LoadExternal 属运行时 API 的定位一致）。
- GLoader3D（骨骼动画）：三套里只有原版有，且依赖 Spine/DragonBones 运行时；静态 HTML 无对应渲染目标，不在补齐范围。

### 4.3 填充策略补齐评估

- fill/align/vAlign/autoSize 当前完全未解析（XML 属性丢弃）。demo 实例中 align/vAlign（center/middle）与 fill="scale" 出现频率很高（Bag 的 icon 格子即此配置），补齐它们比补 url 本身对渲染还原度影响更大。
- CSS 实现路径：fill 计算 sx/sy 后对 `<img>` 设显式 width/height 与 margin（或对组件内容 div 设 transform:scale）；align/vAlign 即绝对定位偏移；autoSize 影响自身尺寸（无 size 属性时取内容原始尺寸）。均为纯计算，无架构阻力。

## 6. 结论与可补齐建议

1. 定性结论：三套实现是同一组件在三种交付形态下的三次投影。原版是"运行时动态加载"的完整实现（ui:// 解析 + 五种 fill + 错误占位 + 换 url）；OpenFairy 按"烘焙优先"哲学把动态加载压缩成编辑期静态快照（运行时零 URL，代价是放弃换 url/shrinkOnly/errorSign）；当前 HTML 渲染器只做了"空 loader 占位"，静态快照这半步尚未迈出。
2. 最划算的补齐顺序（按对渲染还原度的贡献）：
   - 第一步：fill/align/vAlign 样式计算（不依赖 url，空占位也能受益，且 demo 高频）。
   - 第二步：url 指向包内 image 的渲染（parseUiUrl + 复用 image-node，约几十行，覆盖 demo 绝大多数带 url 的 loader）。
   - 第三步：url 指向包内 component 的场景构建（scene-builder 加分支，复用 expandList 模式）。
3. 明确不建议做的：外部 url 加载（无运行时）、GLoader3D 骨骼（无渲染目标）、useResize（依赖 relation 联动，收益低）、showErrorSign（unsupported 清单已承担同等职责）。维持 unsupported 登记即可，与项目"静态渲染、未支持如实登记"的既有约定一致。
4. 注意点：补 url->image 分支时 url 的 item id 需经 parseUiUrl 解析（带 pkgId 前缀消歧），不能直接 `pkg.byId(url)`（url 是 `ui://<pkgId><resId>` 全串而非裸 id）；跨包 component 分支别忘了循环引用防护与 stableKey 续接（expandList 已有范式）。
