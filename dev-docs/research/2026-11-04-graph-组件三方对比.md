## 一、组件定位

GGraph 在 FairyGUI 中对应编辑器里的"图形对象"，源码注释概括了它的双重用途：

1. **显示简单图形**：纯色矩形、椭圆、多边形、正多边形（含描边、圆角），用于占位色块、背景、分隔线、装饰形状等。
2. **占位用途**：运行时可通过 `ReplaceMe` / `AddBeforeMe` / `AddAfterMe` / `SetNativeObject` 把自己替换成任意对象，或在自己前后插入对象，相当于"位置 + 深度"的占位符。这是 FairyGUI 组件扩展的常用手法（例如在代码里把 graph 换成复杂自定义控件）。
3. **运行时动态绘制**：暴露 `shape`（Shape 对象）与一组 `DrawXxx` 方法，业务代码可在运行时重画内容（进度环、自定义多边形、扇形等）。

XML 里的 `type="none"`（缺省）graph 就是一个纯占位节点，不产生任何绘制内容。

## 二、FairyGUI 原版实现要点

### 2.1 类结构

- `GGraph : GObject, IColorGear`：逻辑对象。`IColorGear` 表示它支持 gearColor（颜色齿轮，Gear 隐患 id 4），`color` 属性即填充色，变更时 `UpdateGear(4)`。
- 显示对象是 `Shape : DisplayObject`，内部通过 mesh factory 家族按需生成顶点网格：`RectMesh` / `RoundedRectMesh` / `EllipseMesh` / `PolygonMesh` / `RegularPolygonMesh` / `LineMesh`。
- `Shape.isEmpty` / `Shape.Clear()` 支持运行时清空图形。

### 2.2 运行时绘制 API（Shape 层）

| 方法 | 参数要点 |
|------|----------|
| `DrawRect(lineSize, lineColor, fillColor)` | 矩形，lineSize>0 时描边 |
| `DrawRect(lineSize, Color32[] colors)` | 四角异色矩形（顶点色） |
| `DrawRoundRect(lineSize, lineColor, fillColor, tl, tr, bl, br)` | 圆角矩形，四角半径独立 |
| `DrawEllipse(fillColor)` | 纯填充椭圆 |
| `DrawEllipse(lineSize, centerColor, lineColor, fillColor, startDegree, endDegree)` | 椭圆/扇形（0-360 度范围），中心色与边缘色可形成径向渐变 |
| `DrawPolygon(points, fillColor[, lineSize, lineColor])` | 任意多边形，可选描边；另有顶点色重载 |
| `DrawRegularPolygon(sides, lineSize, centerColor, lineColor, fillColor, rotation, distances)` | 正多边形；`distances` 为每顶点半径比例，可画出星形/不规则放射形 |

GGraph 层包装了 `DrawRect` / `DrawRoundRect` / `DrawEllipse` / `DrawPolygon`（两版）等，先 `SetSize` 再调 Shape。

### 2.3 反序列化（二进制缓冲）与 XML 发布格式

`GGraph.Setup_BeforeAdd` 从包二进制中读：type(byte) → lineSize(int) → lineColor → fillColor → 是否圆角(bool) + 4 个 cornerRadius(float) → polygon 顶点集 → 正多边形 sides/startAngle/distances。type 编码：0=none、1=rect（可圆角）、2=ellipse、3=polygon（自定义）、4=regular polygon。

编辑器发布的 XML 中 graph 节点的属性集（本仓库两份真实工程可核对）：

- 通用属性：`id` `name` `xy` `size` `pivot` `anchor` `scale` `skew` `rotation` `alpha` `visible` `touchable` `group` 等（GObject 通用）。
- graph 专有属性：
  - `type`：缺省 none；`rect`；`ellipse`；`polygon`；`regular_polygon`（或 `regularpolygon`，不同编辑器版本拼写不同）。
  - `lineSize`：描边宽度，0 = 无描边（缺省 0 也会显式写出）。
  - `lineColor`：描边色，`#AARRGGBB`。
  - `fillColor`：填充色，`#AARRGGBB`，缺省白色。
  - `corner`：圆角半径，1 个值（四角同值）或 4 个值（tl,tr,bl,br）。
  - `points`：多边形顶点序列 `"x,y,x,y,..."`（本地坐标，可含小数/负值）。
  - `sides` / `startAngle` / `distances`：正多边形边数、起始角、每顶点半径比例数组（如 `"0.57,0.82,..."`，做出放射/星形轮廓）。
  - `skew`：新版支持斜切（如 `skew="60,30"`）。
  - 新版本另有 polyline（折线）形态与 `roundEdge`（线端圆头）。

拼写注意：老版本编辑器发布椭圆时属性值是 **`eclipse`**（历史拼写错误），新版本为 `ellipse`；正多边形在新工程为 `regular_polygon`，在 CC-Default 工程中为 `regularpolygon`。本仓库两份示例工程即同时存在这两种拼写（UIProject 用 `eclipse`/`regular_polygon`，CC-Default 用 `ellipse`/`regularpolygon`）。

## 三、OpenFairy UGUI 版实现要点

### 3.1 运行时组件：Graph : MaskableGraphic

不复用 uGUI 的 Image，而是 `OnPopulateMesh` 手工生成顶点网格，行为上复刻 FairyGUI 的各 mesh factory（坐标在 FairyGUI y 向下空间计算，AddVert 时翻转到 uGUI 局部坐标）。`Kind` 枚举：`Rect / RoundedRect / Ellipse / Polygon / RegularPolygon / Polyline`。

序列化字段与 FairyGUI 属性一一对应：`lineSize`、`lineColor`、`color`（填充）、`corners[4]`、`points[]`、`sides`、`startAngle`、`distances[]`、`skew`、`roundEdge`。

各形状的网格生成策略：

- **Rect**：lineSize=0 时单个填充 quad；lineSize>0 时四条边框 quad + 内区填充 quad（顶点色区分 lineColor/fill）。
- **RoundedRect**：中心点 + 四角扇形细分（每角按弧长估算分段数），四角半径独立（corners 序列化顺序 tl,tr,bl,br，与 FairyGUI 内部顺序 br,bl,tl,tr 做了映射）；lineSize>0 时内外双层顶点形成描边环。
- **Ellipse**：按周长自适应细分（40-800 边）；额外支持 `startDegree/endDegree` 做**扇形/饼图**（含扇形两条直边的描边与端点圆帽，复刻 EllipseMesh 的 SECTOR_CENTER_TRIANGLES）。该饼图能力为运行时 API（Demo_Graph 在代码里把整圆改扇形），不来自 XML。
- **Polygon**：耳切三角化（ear clipping，复刻 PolygonMesh 的 restIndices 算法）；支持带贴图的百分比多边形（`usePercentPositions` + `texcoords` + `texture`，同为运行时能力）；lineSize>0 时沿轮廓 `DrawOutline` 生成描边条带。
- **RegularPolygon**：sides + startAngle + distances（每顶点半径比例，可画星形/放射形），lineSize>0 描边。
- **Polyline**：折线带状网格（开放路径，沿法线扩宽），`roundEdge` 控制端点圆帽。
- **skew**：任意 Kind 顶点整体斜切变换（以 pivot 为中心）。

### 3.2 相关辅助组件

- `Line : MaskableGraphic`：**不是 graph 的 XML 通道**。它是 FairyGUI `GLine`（运行时线控件，沿 GPath 曲线绘制）的对应物，为 Graph 演示页的折线渲染 helper，支持宽度曲线、渐变、fillStart/End、圆头、贴图。graph 节点的 XML 解析不会走到它。
- `MaskShape : MaskableGraphic`（internal）：蒙版系统的 stencil 形状持有者，按 authored mask 顶点绘制；属于"形状"家族但服务于蒙版烘焙，与 graph 节点解析无直接关系。

### 3.3 Editor 侧 XML 解析（FairyXml.cs + Migrate.cs）

Schema 定义（`Display` 类上的 XmlAttribute）覆盖的 graph 属性：`type`（`ShapeType` 枚举，XmlEnum 处理 `eclipse` 历史拼写与 `regular_polygon`）、`lineSize`（缺省 1）、`lineColor`（缺省 #ff000000）、`fillColor`（缺省 #ffffffff）、`corner`、`points`、`sides`、`startAngle`、`distances`、`skew`、`roundEdge`。

`Migrate.ConfigureShape(Graph, Display)` 的映射逻辑：

- `ellipse` → `Kind.Ellipse`；`polygon`/`polyline` → 对应 Kind，points 按 `"x,y,..."` 逗号拆分为 `Vector2[]`，polyline 附加 `roundEdge`；`regular_polygon` → `sides/startAngle/distances`（distances 同样逗号拆分）。
- 其余（rect/缺省）→ 有 `corner` 时为 `RoundedRect`（**1 个值扩展为 4 角同值**，`radii[min(i, len-1)]`），无 `corner` 时为 `Rect`。
- 通用赋值：`lineSize`、`lineColor`、`color=fillColor`、`skew`。

丢弃/不解析的：XML 中没有 ellipse 的 startDegree/endDegree（扇形）、polygon 的贴图 texcoords——这两类是纯运行时 API，烘焙管线不承载（符合该 SDK"编辑器烘焙可见数据 + 运行时 API 归业务"的发布边界）。

特殊处理：`type=none` 的 graph **不挂 Graph 组件**，只生成纯 `RectTransform`（codegen 字段类型也是 RectTransform）——对应 GGraph 的占位用途。graph 与 image 一样默认可命中（raycastTarget 默认 true，会挡住下层）。Transition 的 Skew 动画目标按 `Graph` 组件处理。

## 四、当前 HTML 渲染器实现要点

相关文件：`src/renderer/nodes/graph-node.ts`（形状渲染）、`src/renderer/gear.ts`（gearColor）、`src/renderer/utils.ts`（toCssColor/baseStyle）、`src/parser/component-parser.ts`（attrs 通用存储）。

解析器把 graph 节点全部属性（type/lineSize/lineColor/fillColor/corner/points/sides/startAngle/distances 等）原样存进 `attrs: Record<string,string>`，渲染层按需取用。当前 graph-node.ts 的实际行为：

| 功能 | 状态 | 实现方式 |
|------|------|----------|
| rect 纯填充 | [已实现] | 缺省分支：普通 div + `background` |
| ellipse 填充 | [已实现] | `type=="ellipse"` 时追加 `border-radius:50%`（非正方形容器下即为椭圆） |
| fillColor | [已实现] | `toCssColor` 把 `#AARRGGBB`/`#RRGGBB` 转 CSS `rgba()`/`#RRGGBB`，缺省 transparent |
| gearColor 默认页覆盖填充 | [已实现] | `resolveGear` 的 color 分支取页值 `"color,stroke"` 的 color 段，覆盖 background |
| 通用几何/外观 | [已实现] | `baseStyle`：xy/size/rotation/flip/alpha（GObject 通用层） |
| lineSize 描边 | [未实现] | lineSize 非空且非 "0" 时记入 unsupported 清单（"graph 描边 lineSize 未实现"），渲染降级为无描边 |
| rect corner 圆角 | [未实现] | `corner` 属性完全不读，圆角矩形静默渲染为直角矩形，**且不记 unsupported** |
| polygon 多边形 | [未实现] | 不识别 type，静默按矩形填充渲染，points 被忽略，**且不记 unsupported** |
| regular_polygon（sides/startAngle/distances） | [未实现] | 同上，静默按矩形渲染 |
| polyline / roundEdge | [未实现] | 同上 |
| ellipse 扇形（startDegree/endDegree） | 不适用 | 属运行时 API，XML 不发布，无需实现 |
| polygon 贴图（texcoords） | 不适用 | 同上 |
| skew 斜切 | [未实现] | graph 专有 skew 未读（通用层 baseStyle 也未处理 skew） |
| type 拼写兼容 | [部分实现] | 只识别 `ellipse`；老拼写 `eclipse` 不命中 border-radius 分支，也**不记 unsupported**，会静默渲染成矩形 |

已知风险点（读代码核实）：

1. **静默降级**：除 lineSize 外，corner/polygon/regular_polygon/eclipse 拼写这些未覆盖项都不会进入 unsupported 清单，页面输出"看起来正常但形状错误"，比显式报缺更难排查。
2. 椭圆用 `border-radius:50%` 在纯填充场景下与 FairyGUI 的 EllipseMesh 视觉等价；一旦要补描边，CSS 圆角边框即可同时覆盖 rect 圆角 + ellipse 描边（见第六节建议）。

## 六、结论与可补齐建议

**结论**：当前 HTML 渲染器覆盖了 graph 最高频的用法（rect/ellipse 纯填充 + gearColor），但对圆角、描边、多边形三类常见装饰能力缺失，且多数缺失是"静默渲染错形"而非显式降级；对老编辑器拼写 `eclipse` 也不兼容。参照 OpenFairy 的解析行为，XML 通道需要关注的属性全集是 `type/lineSize/lineColor/fillColor/corner/points/sides/startAngle/distances/roundEdge/skew`。

**建议按性价比排序**：

1. **拼写归一化 + 补全 unsupported（一行级改动，最先做）**：type 判定同时接受 `ellipse`/`eclipse`；`corner`、`points`、`sides`、`regularpolygon`/`regular_polygon` 等当前未消费的属性出现时记入 unsupported 清单，消除静默错形。
2. **rect 圆角**：读 `corner`（1 值扩展 4 角，对齐 OpenFairy 的 `radii[min(i,len-1)]` 行为），映射 `border-radius`。纯 CSS，零依赖。
3. **rect/ellipse 描边**：lineSize>0 时改用 `border:${lineSize}px solid ${toCssColor(lineColor)}`；ellipse 用 `border-radius:50%` + border 即与 FairyGUI 视觉基本一致，可同步摘掉 lineSize 的 unsupported 记录（仅限这两种 type）。
4. **polygon / regular_polygon**：用内联 `<svg><polygon points=.../></svg>` 或 `clip-path: polygon(...)` 实现。SVG 方案还能顺带解决多边形描边；`distances` 星形可在渲染期把极坐标展开成 points 等价物。若暂不做，至少靠第 1 条保证不再静默错形。
5. **polyline/skew**：低频，保持 unsupported 显式降级即可，等真实工程用到再补。

不建议做的：扇形饼图、多边形贴图、径向渐变（XML 不发布，属运行时 API）、顶点色矩形（无 XML 通道）——引入只会增加无消费者的复杂度。
